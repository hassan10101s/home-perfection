# البيت المثالي — Vue / Nuxt Static

نسخة مستقلة من الموقع العام: ٨ صفحات و٥ مقالات، مع محتوى وصور محلية وروابط وبيانات SEO الأصلية. النشر الحالي مرتبط بفرع `main` على GitHub.

## التشغيل

يتطلب Node.js 24.15 أو أحدث ضمن سلسلة 24، أو Node 22.22.3 فأحدث ضمن سلسلة 22.

```sh
npm ci --legacy-peer-deps
npm run generate
npm run preview
```

المعاينة على `http://127.0.0.1:3000`. أوامر `generate` و`build` و`generate:production` تنتج نسخة إنتاج قابلة للفهرسة. **لنسخة تجريبية محظورة من الفهرسة استخدم `npm run generate:preview` صراحةً.** خادم المعاينة المحلي يضيف noindex في الترويسات افتراضيًا لحماية المعاينة فقط.

إن كان Node النظام قديمًا، يوجد على هذا الجهاز إصدار متوافق في:

```powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" scripts/build.mjs
```

## تعديل المحتوى وصيانته

- `app/pages/`: ملف Vue مستقل لكل رابط؛ أسماء الملفات الرقمية تطابق معرّفات المحتوى القديمة. المسار العام ثابت داخل `definePageMeta` بترميز URL للعربية.
- `content/manifest.json`: فهرس الصفحات والعناوين والروابط، لمعرفة المعرّف المناسب.
- `content/pages/<id>.html`: محتوى الصفحة الأصلي مع تنسيقات Elementor المحفوظة؛ عدّل النصوص والصور هنا. المحتوى مستورد كـHTML ثابت داخل Vue، ولم يُعد بناؤه كاملًا كمكوّنات Vue لكل فقرة.
- مقدمة الصفحة الرئيسية أصبحت مكوّن Vue مستقلًا في `HomeHero.vue`، وبياناتها في `content/home-hero.json`. نفس العنوان والصورة وروابط الأزرار الأصلية، مع تقديم النص والتواصل مبكرًا على الموبايل وتخطيط عمودين على الكمبيوتر.
- `content/pages/<id>.json`: عنوان المتصفح والوصف وcanonical والبيانات المنظمة وأنماط الصفحة. حدّث بيانات SEO مع المحتوى عند الحاجة.
- `app/components/`: الهيدر والفوتر ومكوّن عرض الصفحة ونموذج عرض السعر، كمكوّنات Vue مشتركة مستقلة.
- هيدر الموبايل ثابت أثناء التمرير بارتفاع لا يتغير؛ القائمة تدعم الإغلاق بالخارج وEscape واختيار الروابط، وتوضح الصفحة الحالية مع أهداف ضغط مناسبة للمس.
- زر الاتصال العائم على الموبايل دائرة 58 بكسل بأيقونة SVG محلية، مع مراعاة المساحة الآمنة أسفل الشاشة؛ لا مكتبة أيقونات أو خدمة إضافية.
- فوقه زر واتساب دائري مستقل أخضر، وبينهما مسافة 12 بكسل على الموبايل. الاتصال باللون الكحلي للتمييز، والواتساب رابط مباشر آمن يفتح في تبويب منفصل دون تحميل سكربتات واتساب.
- `app/assets/site.css`: تحسينات العرض والموبايل والمكوّنات المشتركة. تنسيقات الموقع الأصلية محفوظة محليًا تحت `public/wp-content/`.
- `app/assets/polish.css`: اللمسة البصرية الجديدة؛ ألوان أهدأ وأزرار وهيدر وأسئلة شائعة أكثر اتساقًا. لا مكتبة واجهة إضافية.
- `app/assets/home.css`: تخطيط صفحة الهبوط وبطاقات الخدمات. النصوص والتعريفات الأساسية لـSEO لم تتغير، وتم تحسين تباين البطاقات وتسطير روابط النصوص.
- `public/assets/styles/`: تنسيقات مشتركة مخزنة بأسماء ذات بصمة؛ نُقلت من بيانات الصفحات لتقليل JavaScript بأكثر من 1.5 ميجابايت غير مضغوطة عبر الصفحات ومنع تكرار التنسيقات بين الزيارات.
- `public/wp-content/uploads/`: الصور والخطوط مع مساراتها الأصلية للحفاظ على روابط الصور.
- `content/site.json` و`app/plugins/tracking.client.ts`: معرّفات Google الحالية. تعمل فقط في بناء الإنتاج وعلى `homeperfectionnow.com`، بعد موافقة المالك على استعادتها. لا تعمل على localhost أو pages.dev.
- أعيد Statcounter بنفس إعدادات المصدر: المشروع `12888946` ورمز التحقق العام `9e97a520`، مع العداد المخفي. السكربت الرسمي يعمل مرة لكل تحميل صفحة على الدومين الرسمي فقط، وتسمح CSP بنطاقاته المطلوبة.

لإضافة صفحة: أضف ملف Vue على نمط الصفحات الموجودة، وملف محتوى HTML وبيانات JSON، ثم أضف الرابط إلى الفهرس وخرائط الموقع والقائمة عند الحاجة. أعد البناء بعد كل تعديل؛ لا تحتاج قاعدة بيانات أو ووردبريس.

النموذج يفتح واتساب بالتفاصيل ولا يرسل الرسالة تلقائيًا ولا يخزّن البيانات. رقم واتساب المستخدم `966565964755` داخل `QuoteForm.vue`.

## بناء الإنتاج وCloudflare Pages

```sh
npm run generate:production
npm run verify
```

ارفع **محتويات** `.output/public` إلى Cloudflare Pages، بما فيها `_headers` و`_redirects` و`404.html`. أو اضبط أمر البناء على `npm run generate:production` ومجلد الإخراج `.output/public` واستخدم Node 24.22.1.

### Cloudflare Workers المستخدم حاليًا

ملف `wrangler.jsonc` يعرّف Worker باسم `home-perfection` للأصول الثابتة فقط، ومجلد النشر `.output/public`، مع 404 حقيقية وروابط تنتهي بالشرطة المائلة تلقائيًا. لا توجد نقطة دخول JavaScript أو `main` لأن الموقع لا يحتاج سيرفر Nuxt.

أمر Deploy في Cloudflare: `npx wrangler deploy` أو `npm run deploy`. إعداد `build.command` داخل Wrangler يشغّل `npm run build` قبل النشر؛ يمكن ترك Build command المنفصل في اللوحة فارغًا لتجنب بناء الموقع مرتين. Node 24.22.1 وProduction branch `main`.

تم تثبيت نسخة Wrangler في حزم التطوير، وتثبيت Nitro preset على `static` في إعداد Nuxt وبيئة أمر البناء، لمنع اكتشاف المشروع تلقائيًا كمشروع SSR وإنشاء إعداد يبحث عن `.output/server/index.mjs`.

لاختبار تجهيز النشر دون رفعه:

```sh
npx wrangler deploy --dry-run --outdir .data/wrangler-dry-run
```

للرفع على عنوان تجريبي عام استخدم `npm run generate:preview` فقط، أو احمِ المعاينة بواسطة Cloudflare Access. لا ترفع بناء إنتاج قابلًا للفهرسة على عنوان تجريبي عام قبل إعداد الحماية.

تعمل خطوة توليد `_headers` و`robots.txt` من hook داخل Nuxt أيضًا، حتى عند استعمال `nuxt generate` مباشرة. يرفض التغليف أي اختلاف بين وضع البناء وتعليمات الفهرسة في الصفحة الرئيسية. اختبار الفهرسة داخل `verify` يقارن تعليمات كل صفحة بأصلها، بدل فتح صفحات كان حظرها مقصودًا.

قبل تحويل الدومين:

1. خذ نسخة احتياطية كاملة من ووردبريس والقاعدة وإعدادات DNS والبريد، واحتفظ بخطة إعادة الاستضافة القديمة.
2. افحص المعاينة على الموبايل والكمبيوتر. راجع الصفحات الـ١٣ والصور والنموذج و404 والتحويلات.
3. أبقِ `homeperfectionnow.com` هو العنوان الأساسي، ووجّه `www` إليه بتحويل دائم في Cloudflare. حافظ على سجلات البريد MX وTXT وإثبات ملكية Search Console.
4. تأكد أن الإنتاج بلا `noindex` وبلا حظر للزحف، وأن صفحات الموقع ترجع 200 والروابط المجهولة ترجع 404 حقيقية. لا تضف تحويل `/* /index.html 200` لأنه يحوّل الأخطاء إلى صفحات زائفة.
5. افحص ترويسات CSP والأمان في الإنتاج، وأحداث Google بواسطة Tag Assistant؛ لا يمكن اختبار بيانات حسابات Google أو إعدادات الحاوية الخاصة من النسخة العامة وحدها.
6. قدّم `sitemap_index.xml` في Search Console وراجع الفهرسة و404 والزيارات بعد النقل. ثبات الترتيب ليس مضمونًا بمجرد تطابق المحتوى.

## التحقق والأمان

`npm run verify` يقارن العناوين والأوصاف وcanonical وOpen Graph وعدد schema والعناوين الأصلية، ويتحقق من مراجع الصور والروابط الداخلية وغياب سكربتات ووردبريس ومعالجات الأحداث القديمة. النتيجة في `migration/verification.json`.

## تحسين الأداء وتعريف الشركة

يولّد البناء تلقائيًا ملف CSS واحدًا لكل صفحة من تنسيقات المصدر بالترتيب الأصلي، مع استبعاد القواعد غير المستخدمة وضغطها بواسطة `scripts/prepare-styles.mjs`. يظل ملف تنسيقات Vue المشترك مستقلًا: طلبان CSS إجمالًا لكل صفحة. لا تعدّل الملفات المولدة في `public/assets/css/` أو `content/styles-manifest.json`؛ عدّل المحتوى أو المكوّنات وأعد البناء. عند إدخال أسماء classes ديناميكية جديدة أضفها إلى safelist في السكربت وأعد فحص العرض والتفاعلات.

في الرئيسية انخفض CSS الموروث من ١٨ طلبًا و٢٥٦٬٩٥٦ بايت إلى طلب واحد ونحو 44KB قبل ضغط الشبكة. تم فحص العناصر النصية والصور ومقاساتها وألوانها عبر الصفحات الـ١٣ بمقاسي ١٢٨٠ و٣٩٠ بكسل مقارنة بتنسيقات المصدر. تفاصيل الحجم في `migration/css-optimization.json` ونتيجة المقارنة في `migration/ui-regression.json`.

الصورة الرئيسية لها أولوية تحميل، والخطان المحليان المستخدمان مسبقا التحميل. الصور تدعم `sizes` الفعلية وبدائل ٤٨٠ و٦٤٠ بكسل. `scripts/optimize-images.mjs` أداة صيانة اختيارية، وليست جزءًا من كل بناء: تحفظ روابط الصور الأصلية وتضغط الصورة فقط عند توفير ٥٪ على الأقل، وتسجل البصمات لمنع إعادة ضغط الملف نفسه في كل تشغيل. النسخ الاحتياطية المحلية تحت `.data/original-images/` ونسخ Git السابقة. النصوص المرسومة داخل الصور تستدعي مراجعة بصرية بعد أي تغيير في الجودة.

قياس Lighthouse المحلي قبل/بعد التحسين محفوظ في `migration/lighthouse-performance-before.json` و`migration/lighthouse-performance-after.json`. توجد مقارنة أولية في `migration/performance-comparison.json`؛ تُراجع النتائج بعد تغييرات الخلفيات والتباين النهائية. هذا قياس تجريبي محلي بخادم معاينة بلا ضغط HTTP، ولا تعمل عليه أكواد التتبع المقيدة بالدومين؛ لا يمثل درجة الإنتاج أو ضمانًا ثابتًا للأداء. لم تتغير أكواد Google أو Statcounter، وقد تبقى كلفة سكربتات GTM في قياس الإنتاج.

`content/company.json` مصدر موحد للاسم والهاتف والبريد والخدمات ومناطق الخدمة وروابط الصفحات المؤيدة لها. البناء يولد `public/company.json` بصيغة JSON-LD و`public/llms.txt` كملخص مقروء آليًا، وتظهر بيانات التواصل في صفحة «من نحن». جُمعت كيانات الشركة المتكررة في schema تحت معرّف واحد، مع حفظ بيانات الصفحات وبقية الحقول القديمة. لم تُضف تقييمات أو أسعار أو تراخيص أو ساعات عمل جديدة. حدّث الملف المصدر فقط ثم أعد البناء. هذه الملفات تساعد على وضوح المعلومات ولا تضمن ظهور الشركة في نتائج محركات البحث أو إجابات أدوات الذكاء الاصطناعي.

يتحقق `verify` أيضًا من أن Nitro يستخدم preset `static`، ومن غياب مدخل سيرفر `.output/server/index.mjs`، ومن أن Wrangler يرفع `.output/public` فقط دون `main`. أدوات CSS والصور والبناء كلها حزم تطوير لا تعمل لدى الزائر ولا تحتاج خدمة خارجية.

`migration/baseline.json` يسجل مصدر النقل. رابطا `/company-services/` و`/نقل-عفش-الرس/` كانا يرجعان 404 في المصدر؛ وُجّه الأول إلى خدمات الرياض والثاني إلى خدمات القصيم، مع تحديث الروابط الداخلية. لا توجد مادة منشورة لهما ضمن المحتوى المستخرج.

الخروج النهائي ملفات ثابتة فقط: لا PHP ولا لوحة إدارة ولا أسرار ولا قاعدة بيانات. CSP يولّد بصمات لسكربتات Nuxt المضمّنة بدل السماح العام بـunsafe-inline للسكربتات. السماح بالأنماط المضمّنة ضروري للحفاظ على تصميم Elementor الأصلي.

استُخدم Nuxt 4.6.2 لتضمين إصلاحات الأمان المتاحة. بقي تحذير تدقيق متعلق بـ`node-forge` عبر أدوات البناء `listhen`/`nitropack`؛ لا تُرفع أدوات البناء أو `node_modules` إلى Cloudflare. شغّل البناء من مصدر موثوق، وأعد تدقيق الحزم وتحديثها عند توفر إصلاح. لا تشغّل خادم التطوير للعامة.

أداة `scripts/migrate.mjs` خاصة باستخراج الموقع القديم، وليست مطلوبة للبناء أو التشغيل. النسخ الخام في `migration/raw/` مستبعدة من Git؛ لا تعِد الاستخراج بعد نقل الدومين إلى النسخة الثابتة.

أزيلت قواعد Elementor التي تخفي خلفيات الأقسام انتظارًا لسكربت ووردبريس غير الموجود في النسخة الثابتة، وبذلك عادت الخلفيات والصور المقصودة. أصبحت مقدمة حساب التكلفة HTML نظيفًا بلا أعمدة Elementor الفارغة أو بقايا Contact Form 7، مع نفس النص والعناوين. صُححت أيضًا ألوان ملاحظات الأسعار وتعليق الفيديو وروابط تنقل المقالات. فحص التباين المحسوب على الخلفيات المصمتة في الصفحات الـ١٣ بمقاسي الكمبيوتر والموبايل موثق في `migration/contrast-review.json`؛ الخلفيات المتدرجة والصور تستدعي المراجعة البصرية ولا تدخل حسابه الآلي.

الفحص النهائي لصفحة حساب التكلفة: SEO والإتاحة ١٠٠ في `migration/lighthouse-quote-final.json`. أصبح النص التوضيحي فقرة بدل عنوان H4 غير متسلسل، مع حفظ النص حرفيًا. تعذر القياس النهائي للأداء مرتين بسبب خطأ تتبع Lighthouse `NO_NAVSTART`؛ لا تُنسب الدرجة الأولية ٧٦ إلى النسخة النهائية، وتفاصيل الحالة في `migration/lighthouse-final-status.json`.
